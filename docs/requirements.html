1 プロダクト概要

🎯ターゲット
  • 新入社員・アルバイトスタッフ（質問するユーザー）
  • バックオフィス担当者（資料管理・FAQ 管理）
  • AI・システムに疎い業種不問の企業
💡コンセプト
  • 社内規約・マニュアルを AI が参照して回答
  • ChatGPT ライクなわかりやすい UI
  • 資料を管理画面からアップロードするだけで動く
🏗️マルチテナント
  • サブドメイン（{orgSlug}.app.example.com）で組織を識別
  • 全データは organization_id スコープで分離
  • 各組織が個別の AI API キーを持てる設計
📦技術スタック
  • Next.js 16 / React 19 / Tailwind CSS v4
  • PostgreSQL + Prisma 7
  • Groq SDK（メイン）/ Anthropic SDK（フォールバック）
  • AWS Secrets Manager + S3

2 解決する課題

  • 😤 上司・先輩への問い合わせ工数が多い — 新人が「有給はいつから？」「休憩は何分？」のような基礎的な質問を都度聞いてしまう
  • 📄 社内規約を自力で探せない — 就業規則 PDF がどこにあるか分からず、見つけても該当箇所を読み解けない
  • ⏳ 新人教育の立ち上がりが遅い — 教える側・教わる側の両方に時間がかかり、戦力化が遅れる
  • 🌐 業種・会社ごとにルールが違う — 汎用的な Q&A ではなく、その会社の資料に基づいた回答が必要

3 ユーザー要件（一般社員・アルバイト）

3-1. 質問・回答

  • 💬 自然言語で質問できる — テキストエリアに普通の日本語で入力。Enter で改行、Cmd+Enter で送信 実装済み
  • 🔍 プレースホルダーに例文（「休憩は何分取れますか？」）を表示して入力イメージを伝える 実装済み
  • 📝 回答は構造化されて表示される — 結論 → 根拠 → 補足 → 注意点 → 相談先 の順序 実装済み
  • 📎 回答には出典（資料名・セクション）を表示する 実装済み
  • 🔁 追加質問ができる — 同一スレッド内で文脈を引き継いで追加質問を送れる 実装済み
  • ❌ 回答が見つからない場合 — 「回答が見つかりませんでした」を表示。資料不足以外の理由はシステム上受け付けない 実装済み
  • 🔗 回答が見つからない場合は関連 FAQ を最大 3 件表示する 実装済み

3-2. フィードバック

  • 👍 「役に立った / 立たなかった」のフィードバックを各回答に表示。DB に保存して精度改善に活用 実装済み

3-3. 担当者へのエスカレーション

  • 📤 担当者に相談を送れる — 「担当者に送る」ボタン → 質問をコピー → 本文を再入力 → 送信確認ダイアログの 3 ステップ 実装済み
  • 📋 質問文をコピーするボタンを用意する（口調が異なるため再入力させる設計） 実装済み

3-4. 質問履歴

  • 📚 過去の質問をサイドバーに一覧表示 — リロード後も履歴が残る（DB 永続化） 実装済み
  • 📌 スレッドをピン留めできる 実装済み
  • 🗒️ スレッドに自分用メモを記入できる 実装済み
  • 🗑️ スレッドを削除できる（論理削除。管理データは残る） 実装済み

3-5. よくある質問（FAQ）タブ

  • 📋 FAQ タブを切り替えてよくある質問を閲覧できる 実装済み
  • 🏷️ カテゴリでフィルタできる（例: 入社初日・勤怠・服装・有給） 実装済み
  • 🏆 ランキング順（実際に質問された回数の多い順）でも表示できる 実装済み

3-6. 認証

  • ✉️ メールアドレス + パスコード（パスワードレス）でログイン — メールに 6 桁コードを送付。10分有効。ロックアウト・レート制限対応 実装済み
  • 🔬 オプション: パスキー（生体認証 / WebAuthn） — FIDO2 準拠。登録・認証・管理（/settings）実装済み 実装済み

4 管理者要件

4-1. 資料管理

  • 📁 資料をアップロードできる — PDF / TXT（MVP）。将来: Word / Excel 対応予定 実装済み
  • ☁️ アップロードしたファイルはS3 互換ストレージに保管し、テキスト抽出して AI に利用させる 実装済み
  • 📄 現在利用中の資料一覧を確認できる 実装済み
  • 🗑️ 資料を削除できる（論理削除。過去の質問への参照は残る） 実装済み
  • 🔗 Google Drive / Box のフォルダを指定して自動同期できる 実装済み（本番テスト待ち）

4-2. FAQ 管理

  • ✏️ FAQ を作成・編集・削除できる — 質問文・回答（結論/根拠/補足/注意/相談先）・カテゴリ・公開フラグ 実装済み
  • 👁️ FAQ は下書き状態で保存できる — isPublished: false の間はユーザーに見えない 実装済み
  • 🔗 未回答一覧から「FAQ に追加」ボタンで FAQ 作成画面に遷移できる 実装済み

4-3. カテゴリ管理

  • 🏷️ カテゴリの作成・編集・削除・並び順変更ができる 実装済み
  • 💡 デフォルトカテゴリ例: 入社初日に多い質問 / 勤怠・シフト / 服装・持ち物 / 有給・休憩 / 店舗ルール / トラブル時

4-4. 未回答一覧

  • ❓ AI が回答できなかった質問の一覧を確認できる — 最近順・頻度順でソート 実装済み
  • 🔔 未回答が発生したときSlack 等へ通知が届く 実装済み

4-5. ランキング

  • 🏆 質問ランキングを確認できる — 期間指定・上位 N 件。どの質問が多いかを把握して FAQ 整備に活用 UI のみ（API 未接続）

4-6. 組織設定

  • 🎨 ブランドカラー・ロゴ・表示文言をカスタマイズできる（ウェルカム画面・タブ名など） 実装済み
  • 🔑 AI API キーの設定状況を確認できる — キーの登録は GrowDays 担当者が Secrets Manager に直接登録 実装済み
  • 🔗 Google Drive / Box の連携設定ができる — OAuth 認証・フォルダ選択・同期 ON/OFF 実装済み（本番テスト待ち）
  • 🔔 通知先（Slack / email）を設定できる 実装済み

4-7. 管理者認証・ユーザー管理

  • 🔒 組織ごとに管理者アカウントを管理できる — ロール: admin / member 実装済み
  • ➕ 管理画面からユーザーを追加できる（追加されたユーザーにパスコードをメール送付）。編集・削除・ロール変更も可能 実装済み

5-2. 回答フォーマット（AI が返す構造）

フィールド内容必須
conclusion結論（1〜2文）✅
evidence根拠となる規則・条文✅
supplement補足情報任意
caution注意点任意
contact相談先✅
sources引用資料（title / section / documentId）の配列✅
matchedFaqId一致した FAQ の ID（なければ null）✅

5-3. FAQ 優先・asked_count 更新

  • ⭐ AI は FAQ と資料の両方を参照し、FAQ に一致する場合は FAQ を優先して回答する。matchedFaqId を返すことで特定。
  • 📊 matchedFaqId が返った場合はアプリ層で faqs.asked_count を +1 する（DB トリガー不使用）

6 外部連携要件

6-1. Google Drive / Box 自動同期

  • 🔗 管理者がフォルダを指定すると、フォルダ内のファイルを定期的に自動取り込みする
  • 🔑 OAuth 認可は組織ごとに管理者が自分のアカウントで行う
  • 🔒 リフレッシュトークンはAES-256-GCM で暗号化して DB に保存（ENCRYPTION_KEY を Secrets Manager で管理）
  • ⏱️ 同期間隔: デフォルト 1 時間（SYNC_INTERVAL_HOURS 環境変数で変更可能）

6-2. 対応ファイル形式

形式Google DriveBox手動アップロード

Google ドキュメント✅（text/plain エクスポート）——
Word (.docx)✅✅❌（MVP 外）
Excel / Sheets❌❌❌
画像・スキャン PDF❌（OCR は将来対応）❌❌

6-3. 通知（Slack / email）

  • 🔔 未回答が発生したとき・エスカレーションが送信されたとき、設定した通知チャネルへ送信する 実装済み
  • 🛠️ 対応チャネル: Slack（Block Kit 形式）・email（Resend API）。複数チャネル同時設定可能。開発時はコンソール出力

7 認証・セキュリティ要件

7-1. 認証方式

対象方式状態
一般ユーザー（フロント）メールアドレス + パスコード（6桁・10分有効）実装済み
管理者（管理画面）同じくパスコード認証（/admin/login 専用ページ）実装済み
オプション（全ユーザー）パスキー（WebAuthn / FIDO2 生体認証）実装済み
開発用モックPOST /api/auth/mock-login（本番では 404）開発用のみ
セッション管理 セッションは DB（auth_sessions テーブル）で管理。Cookie に HMAC-SHA256 署名付きトークンを保存。 proxy.ts がすべてのリクエストで署名を検証し、未認証リクエストを /login または /admin/login にリダイレクトする。

7-2. セキュリティ要件

  • 🔑 API キーは NEXT_PUBLIC_ を絶対に付けない — サーバーサイド専用
  • 🏦 本番の API キー・DB パスワードは AWS Secrets Manager で管理（.env ファイルにベタ書き禁止）
  • 🔐 OAuth リフレッシュトークンは AES-256-GCM 暗号化して DB に保存
  • 🚫 500 エラーのレスポンスに スタックトレース・DB エラー・ファイルパスを含めない
  • 🙈 ログに PII（パスワード・パスコード・API キー・メールアドレス）を出力しない（自動サニタイズあり）
  • 🍪 セッション Cookie は httpOnly; Secure; SameSite=Lax、有効期限 7 日
  • 🔒 ログイン失敗は 60 分で 5 回でロックアウト（15 分）。失敗時のメッセージは「メールアドレスまたはパスワードが正しくありません。」に統一
  • 🌐 NODE_TLS_REJECT_UNAUTHORIZED=0 は開発環境のみ。本番で使用禁止

9 用語集

用語説明
ユーザー社員・アルバイトなど、その組織で働く人間。フロント画面から質問する側。
管理者（admin）資料・FAQ・カテゴリ・設定を管理するバックオフィス担当者。
組織（Organization）マルチテナントの単位。1 社 1 テナント。スラッグ（例: sprout）でサブドメインを形成する。
スレッド（QueryThread）1 つの会話全体。最初の質問から始まる追加質問のまとまり。
クエリ / turn（Query）スレッド内の 1 発話（ユーザーの質問 + AI の回答のペア）。
FAQ管理者が手動で作成したよくある質問と回答。AI が優先的に参照する。
資料（Document）管理者がアップロードした規約・マニュアル等の PDF / TXT。テキスト抽出して AI に渡す。
エスカレーションユーザーが回答に納得できず担当者に相談内容を送る機能。
per-org キー各顧客組織が契約した AI API キー。Secrets Manager の onboarding/{orgId}/api-key に保管。
asked_countFAQ が実際に質問にマッチした回数。ランキング表示・FAQ 優先度の判断に使う。
