1
サブフォルダのファイルも取り込むか？
指定フォルダの直下のみ同期するか、その中のフォルダも再帰的に取得するか
影響大
A
フォルダ直下のみ（1階層）
推奨
指定したフォルダの中にあるファイルだけを対象にする。サブフォルダの中身は取得しない。
実装がシンプル、意図しないファイルの混入リスクが低い フォルダ整理をしていると複数フォルダを登録する必要がある
B
サブフォルダを再帰的に全取得
指定フォルダ以下のすべてのファイルを対象にする（何階層でも）。
フォルダ1つ指定するだけで完結する 意図せず大量ファイルが取り込まれるリスク、処理時間が読めない
この決定が影響すること

同期処理のコード量とテスト範囲に差が出ます。A → B への変更は後からでも比較的容易です。まず A で始めて、要望があれば B に拡張することを推奨します。

2
連携を解除したとき、取り込み済みのファイルはどうするか？
管理者が「接続解除」したとき、すでにシステムに取り込まれたドキュメントをどう扱うか
影響中
A
論理削除する（検索対象から外す）
推奨
接続解除と同時に、そのプロバイダ経由で取り込んだドキュメントをすべて「削除済み」扱いにする。Claude の回答の出典からも除外される。
データが一貫する、「切ったら終わり」でわかりやすい 再接続すると再度同期が必要になる
B
そのまま残す（手動で個別削除）
接続解除しても取り込み済みのドキュメントは残り、引き続き検索対象になる。管理者が必要なら手動で1件ずつ削除する。
再接続しても差分だけ同期できる 削除し忘れると古い資料が検索に残り続ける
この決定が影響すること

接続解除の API 実装と、管理画面のドキュメント一覧の設計に影響します。A の場合は解除時に一括更新する処理が入ります。

3
同期が失敗したとき、管理者に通知するか？
トークン失効やAPI障害で同期が止まったとき、どう知らせるか
影響中
A
管理画面にエラーを表示するだけ（通知なし）
推奨
同期エラーは管理画面の「連携設定」ページにエラーメッセージを表示するだけ。Slack/メール通知は送らない。
実装が最小限、通知チャネルの設定が不要 管理者が気づかない可能性がある
B
既存の通知チャネル（Slack・メール）に送る
未回答通知と同じ notification_channels を使って Slack やメールでエラーを知らせる。
即時に気づける、放置リスクが低い 通知チャネルが未実装なので同時実装が必要になる
補足： 通知チャネル（Slack・メール送信）は実装済みです。notification_channels テーブルへの設定があれば、同期エラー時も同チャネルへ通知を送ることができます。
4
フォルダはどうやって選ばせるか？
管理者が「このフォルダを同期する」と指定する UI の方式
影響小
A
Picker API（フォルダブラウザ）
推奨
Google Drive Picker / Box Content Explorer を埋め込んで、 実際のフォルダツリーをクリックして選ぶ。フォルダ ID を手入力する必要がない。
操作が直感的、ID 入力ミスがない 追加の JavaScript SDK 読み込みが必要
B
フォルダ ID を直接テキスト入力
Drive/Box の URL や設定画面からフォルダ ID をコピーして、テキストボックスに貼り付ける。
実装が最もシンプル ID の調べ方が非エンジニアにはわかりにくい
この決定が影響すること

管理画面の UI 実装量に差が出ますが、バックエンド（同期処理）には影響しません。B で先に動かして、後から A に変えることも容易です。
